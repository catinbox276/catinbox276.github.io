## 📌 MLOps 강의 정리 1

오늘 강의에서는 **기존 머신러닝 시스템의 한계점**을 짚으면서, 왜 **MLOps가 필요한지**에 대한 인사이트를 얻을 수 있었다.

### ✅ 기존 조직의 한계와 변화

과거에는 ML 모델이 조직 내에서 **새로운 영역**이었고, 다뤄야 할 모델 수도 적어서 큰 문제가 되지 않았다. 하지만 최근 들어 **의사결정 자동화**가 늘면서 모델이 **기업 전략의 핵심**으로 자리 잡고 있다.
→ 그만큼 **모델 리스크 관리**, **모델 생애주기 관리**, **실시간 데이터와 비즈니스 요구사항 반영**이 중요한 과제가 되었다.
이 과정에서 자연스럽게 **MLOps의 필요성**이 대두된다.

## 💼 데이터 직무별 역할과 협업

| 직무         | 필요 역량 및 특징                                                |
| ---------- | --------------------------------------------------------- |
| 데이터 엔지니어   | 소프트웨어 엔지니어링 역량 중심, 수학·통계·ML 알고리즘 지식 필요, 협업과 커뮤니케이션 역량도 중요 |
| 데이터 분석가    | 수학·통계·알고리즘 기반 분석 역량 + 데이터 커뮤니케이션 역량 (협업 필수)               |
| 데이터 사이언티스트 | 엔지니어 + 분석가 역량 모두 요구됨, 국내에서는 분석가와 혼용되기도 함                  |

→ 결국 **모든 직무는 서로 연결**되어 있고, **협업**이 핵심이다.
특정 역량에 집중하되, 점진적으로 **지식의 폭을 넓혀가는 방향**이 바람직.

---

## 🧱 데이터 과학 생태계 구조

전체 데이터 과학 플로우는 아래와 같은 **계층 구조**로 설명됨:

1. **데이터 수집**
2. **저장 및 이동**
3. **탐색 및 전처리 (ETL/ELT)**
4. **모델 학습 및 최적화**

→ 하단으로 갈수록 **데이터 엔지니어 중심**, 상단으로 갈수록 **데이터 분석가/사이언티스트 중심**.
→ 규모가 큰 기업일수록 **데이터 수집, 저장, 인프라 중요성**이 커짐.

---

## 🔄 머신러닝 시스템 구성 요소

머신러닝 시스템을 구성하는 단계는 다음과 같다고 함:

1. **데이터 수집/저장/전처리 (ETL/ELT)**
2. **컴퓨팅 리소스 관리**
3. **오케스트레이션 (Airflow, Kubeflow 등)**
4. **버저닝 (데이터, 코드, 실험 등)**
5. **배포 (모델 서빙 환경 포함)**
6. **모델링 컴포넌트 (학습 및 추론)**

→ 아래로 갈수록 인프라/엔지니어링 역량, 위로 갈수록 분석 역량이 요구됨
→ 특히 **버저닝과 배포 단계**에서는 다양한 도구와 협업이 필수

---

## 📦 학습과 추론의 분리

ML은 결국 **복잡한 함수 근사**를 위한 시스템이며,
**학습(Training)**: 정제된 데이터 + 알고리즘 → 모델 가중치 생성
**추론(Inference)**: 학습된 모델 + 새로운 데이터 → 예측값 생성

→ 이 두 단계를 명확히 **분리해서 이해하는 것**이 매우 중요
→ 딥러닝 모델은 특히 **블랙박스 성격**이 강해 해석이 어려운 경우가 많음

---

## 🔍 머신러닝의 장단점

**장점**

* 복잡한 패턴 처리
* 적응성 및 자동화
* 확장성, 일반화 능력

**단점**

* 데이터 의존성 높음
* 해석 어려움 (블랙박스)
* 계산 리소스 비용 큼
* 편향, 과적합 가능성 있음

→ 문제의 성격에 따라 **룰 베이스 vs ML 베이스**를 **적절히 선택**해야 함

---

## ⚙️ ML 프로젝트의 워크플로우

1. **비즈니스 문제 정의**
   → 가장 중요한 단계, *ML로 풀 수 있는 문제인지*부터 확인해야 함
   → 흔한 실수: 문제 정의 없이 모델링부터 시작

2. **데이터 수집 및 전처리 (EDA 포함)**
   → 피처 선택, 파이프라인 구축 필요
   → 정확성, 신뢰성, 접근 권한, 레이블링 등 고려할 요소 많음

3. **모델 학습 및 튜닝**
   → 하이퍼파라미터 최적화 포함

4. **모델 평가 및 검증**
   → 성능 측정, 과적합 여부 판단

5. **배포 (서빙 환경 포함)**
   → 데이터 사이언티스트 ↔ 소프트웨어 엔지니어 간 협업 필수
   → 환경 구성 및 배포 자동화 중요

6. **모니터링 및 피드백 루프**
   → 데이터 드리프트 감지, 성능 저하 시 재학습
   → **자동화가 핵심**

---

## 📎 현실 사례와 데이터 관점

* **Same Data, Different Conclusions**
  → 같은 데이터도 해석 방법에 따라 결론이 달라질 수 있음 → *비판적 사고 필수*

* **더닝 크루거 효과 / 파워 포징 사례**
  → 데이터 기반 정보라도 맹신 금물 → *검증과 의심의 태도 필요*

* **생존자 편향 (전투기 구멍 분석)**
  → 보이는 데이터뿐만 아니라, *보이지 않는 데이터*도 고려해야 정확한 결론 도출 가능

* **화학 공정 최적화 사례**
  → 이미 최적화된 시스템에선 데이터로 더 나은 인사이트를 얻기 어려움 → *도메인 지식과 현업 이해 중요*

---

## 🧪 실험과 관리

모델 학습에서 다뤄야 할 요소들:

* **입력값**: 데이터셋, 수행 파라미터(날짜 등), 하이퍼파라미터
* **출력값**: 모델 가중치 파일, 지표, 로그, 추론 결과 등

→ 이 모든 **아티팩트는 컨테이너 환경에서 휘발성**이기 때문에
→ 별도 스토리지에 **영구 저장 및 관리**가 필요

---

## 🛠 워크플로우 자동화 도구

* **Airflow, Kubeflow 등**
  → 데이터 수집부터 모델 서빙까지의 프로세스를 자동화
  → 자원 효율적 관리 가능
  → 단, 휘발성 이슈로 인해 **결과 저장소** 연동 필수

도구 선택 시 고려사항:

* 기업 환경 적합성
* 인프라 준비 상황
* 커뮤니티 및 유지보수 수준

## 🧭 MLOps 성숙도 단계 (Google 기준)

| 레벨 | 설명                                           |
| -- | -------------------------------------------- |
| 0  | 대부분 수동. 재현 불가, 자동화 없음                        |
| 1  | 일부 파이프라인 자동화. 재현 가능. 실험 환경 일관성 확보            |
| 2  | 완전 자동화. CI/CD + 자동 모니터링 + 피드백 루프. 효율적인 운영 가능 |

## 🔚 정리하며

MLOps는 단순한 기술 도입이 아니라,
**ML 모델의 전체 생애주기를 안정적이고 효율적으로 관리하기 위한 총체적인 접근 방식**이다.

* 직무 간 협업 중요
* 커뮤니케이션 능력 필수
* 데이터를 비판적으로 바라보는 시각 필요
* 자동화와 시스템화가 핵심
